# Lab Objective

In this lab, we will customize the Kubernetes Deployment template for our API Gateway.

Instead of using the generic Deployment generated by `helm create`, we will modify it to deploy our Enterprise DevOps Platform API Gateway.

After this lab, the Deployment template will read configuration from `values.yaml`.

# Step 1

Open the Deployment template.

```bash
nano helm/charts/api-gateway/templates/deployment.yaml
```

---

# Step 2

Replace the generated Deployment with the following template.

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: {{ .Release.Name }}-api-gateway

spec:
  replicas: {{ .Values.replicaCount }}

  selector:
    matchLabels:
      app: api-gateway

  template:

    metadata:
      labels:
        app: api-gateway

    spec:

      serviceAccountName: {{ .Release.Name }}-api-gateway

      containers:

      - name: api-gateway

        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"

        imagePullPolicy: {{ .Values.image.pullPolicy }}

        ports:

        - containerPort: {{ .Values.service.port }}

        resources:

{{ toYaml .Values.resources | indent 10 }}
```

# Production Best Practices

- Never hardcode image names.
- Always reference values from `values.yaml`.
- Use resource requests and limits.
- Keep Deployment templates reusable.
- Validate every template change using `helm lint`.
- Review rendered YAML using `helm template` before deployment.

---

# Common Mistakes

- Hardcoding replicas.
- Hardcoding Docker image tags.
- Incorrect Helm template syntax.
- Invalid YAML indentation.
- Ignoring `helm lint` warnings.
- Deploying without reviewing rendered manifests.

# Interview Questions

## Q1. Why use `{{ .Values }}` in Deployment templates?

### Answer

`{{ .Values }}` allows the Deployment template to read configuration dynamically from `values.yaml`, enabling the same chart to be reused across multiple environments.

---

## Q2. What does `helm template` do?

### Answer

`helm template` renders Helm templates into plain Kubernetes YAML without deploying them to the cluster. It is commonly used for validation and troubleshooting.

---

## Q3. Why should engineers avoid hardcoded values in Deployment templates?

### Answer

Hardcoded values reduce reusability and make environment-specific deployments difficult. Using Helm values enables configuration changes without modifying templates.
