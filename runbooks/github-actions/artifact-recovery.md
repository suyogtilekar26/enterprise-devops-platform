# Runbook - GitHub Actions Artifact Recovery

## Purpose

This runbook provides the standard operating procedure for recovering build artifacts generated by GitHub Actions.

Artifacts are used to store files generated during CI/CD pipelines, including

- Build outputs
- Test reports
- Coverage reports
- Deployment manifests
- Logs
- Release packages

This runbook applies when artifacts are missing, corrupted, expired, or unavailable for deployment or troubleshooting.

---

# Severity

Applicable to

- SEV-3
- SEV-4

Escalate to SEV-2 if production deployment depends on unavailable artifacts.

---

# Symptoms

Examples

- Artifact download failed
- Artifact not found
- Artifact expired
- Corrupted artifact
- Deployment job cannot locate artifact
- Workflow reports

```
Artifact does not exist
```

or

```
Failed to download artifact
```

---

# Prerequisites

Ensure access to

- GitHub Repository
- GitHub Actions
- Workflow Runs
- Repository Permissions
- Build Logs

---

# Investigation

## Step 1

Open GitHub Actions.

Navigate

```
Repository

↓

Actions

↓

Workflow Run
```

Verify

- Workflow completed
- Artifact upload step executed
- Artifact name

---

## Step 2

Review Upload Artifact step.

Verify

```
actions/upload-artifact
```

completed successfully.

Record

- Artifact Name
- Upload Status
- Upload Path

---

## Step 3

Review Download Artifact step.

Verify

```
actions/download-artifact
```

Review any error messages.

---

## Step 4

Verify artifact retention period.

Confirm the artifact has not expired.

---

## Step 5

Verify artifact name.

Ensure upload and download steps reference the same artifact name.

Example

Upload

```yaml
name: build-output
```

Download

```yaml
name: build-output
```

Names must match exactly.

---

## Step 6

Verify upload path.

Example

```yaml
path: dist/
```

Ensure the directory existed before upload.

---

## Step 7

Verify build completed successfully.

If the build failed, no artifact may have been generated.

---

# Resolution

## Artifact Never Uploaded

Correct the upload step.

Example

```yaml
- uses: actions/upload-artifact@v4
```

Re-run the workflow.

---

## Incorrect Artifact Name

Use the correct artifact name in both upload and download steps.

---

## Invalid Upload Path

Correct the path.

Verify files exist before upload.

---

## Artifact Expired

Re-run the workflow to generate a new artifact.

---

## Corrupted Artifact

Delete the failed workflow run if appropriate.

Generate a fresh artifact using a new workflow execution.

---

# Verification

Confirm

- Artifact uploaded successfully
- Artifact visible in Workflow Summary
- Artifact downloaded successfully
- Deployment resumes successfully
- No workflow errors

---

# Rollback

If artifact recovery is unsuccessful

- Re-run the previous successful commit
- Generate a new artifact
- Continue deployment using the regenerated artifact

Avoid manually modifying artifact contents.

---

# Escalation

Escalate when

- Artifact repeatedly fails to upload
- Artifact repeatedly fails to download
- Multiple workflows affected
- Production deployment blocked
- GitHub Actions service issue suspected

Notify

- DevOps Lead
- Platform Team
- Application Owner

---

# Post-Incident Tasks

- Document root cause
- Review artifact retention settings
- Validate upload paths
- Verify workflow reliability
- Update documentation if required

---

# Recovery Checklist

- Artifact generated
- Artifact uploaded
- Artifact downloaded
- Workflow completed
- Deployment successful
- Monitoring normal
- Incident closed
